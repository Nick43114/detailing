# Сайт-застосунок детейлінг-студії (PWA)

Відкривається за посиланням у браузері телефона, без магазинів застосунків. За бажанням клієнт додає його на головний екран («Додати на головний екран»). Інтерфейс українською, дизайн для телефона.

Розділи: **Головна, Послуги, Запис, Питання, Контакти** + прихований **кабінет власника** (посилання «Вхід для власника» внизу розділу «Контакти», адреса `…/#/owner`).

## Що де лежить

| Файл | Призначення |
|---|---|
| `studio-config.js` | **Єдиний файл даних студії**: назва, логотип, фото, послуги, ціни, графік, боксі, контакти, питання й відповіді, ключі бази |
| `supabase.sql` | Структура бази даних (виконати один раз) |
| `index.html`, `styles.css`, `app.js` | Інтерфейс |
| `core.js` | Розрахунок вільного часу, дати, телефони |
| `api.js` | Зв’язок із базою (Supabase) і демо-режим |
| `manifest.webmanifest`, `sw.js`, `assets/` | PWA: маніфест, офлайн-кеш, іконки, фото-заглушки |

## Як рахується вільний час

- Робочі години й вихідні — `schedule.days` у `studio-config.js`; кількість боксів — `schedule.boxes`.
- Запис займає бокс на **тривалість послуги + 15 хв запасу** (`bufferMinutes`). Останній клієнт має закінчити роботу до закриття.
- Двох записів на один бокс і час бути не може: це гарантує **сама база даних** (обмеження на перетин), навіть якщо двоє клієнтів натиснуть «Записатися» одночасно. Програвший побачить повідомлення «час щойно зайняли» й оновлений список годин.
- Години рахуються за часовим поясом студії (`timezone`), а не клієнта.

## Підключення бази Supabase (~15 хвилин)

1. Зареєструйтеся на supabase.com (безкоштовний тариф підходить) → **New project**. Запам’ятайте пароль бази (він нам не потрібен, але його не можна відновити).
2. **Authentication → Users → Add user → Create new user**: вкажіть email власника й **пароль** (це пароль для входу в кабінет), поставте галочку *Auto Confirm User*.
3. **Authentication → Sign In / Providers → Email**: вимкніть **Allow new users to sign up** (щоб ніхто сторонній не міг створити обліковий запис).
4. Відкрийте `supabase.sql`, замініть у ньому `owner@example.com` на email із кроку 2. **SQL Editor → New query** → вставте весь файл → **Run**. Повідомлення «Success» — готово.
5. **Project Settings → API Keys** (або *Data API*): скопіюйте **Project URL** і **publishable key** (старий варіант називається *anon public*). У `studio-config.js`:
   ```js
   supabase: { url: "https://….supabase.co", anonKey: "sb_publishable_…" },
   owner:    { email: "той самий email із кроку 2", … }
   ```
   **Секретні ключі (`secret`, `service_role`) у файл не вставляйте** — він публічний.
6. Завантажте файли на хостинг (нижче) і перевірте: зробіть тестовий запис → увійдіть у кабінет → запис має з’явитися в «Нових».

Поки `supabase.url` порожній, застосунок працює в **демо-режимі** (позначка «демо» вгорі): записи й правки живуть лише в браузері цього пристрою; пароль кабінету — `owner.demoPassword` (за замовчуванням `demo1234`). Для реальної роботи демо-режим не годиться.

## Публікація (щоб відкривалося за посиланням)

Будь-який статичний https-хостинг: **Netlify** (Add new site → Deploy manually → перетягнути папку), **Cloudflare Pages**, **GitHub Pages**. Збирати нічого не потрібно. Після публікації посилання можна давати клієнтам; на телефоні воно відкривається без встановлення, а меню браузера пропонує «Додати на головний екран».

## Що змінює власник у кабінеті

- **Записи** — нові, майбутні, скасовані; підтвердити / скасувати / відновити. Скасування звільняє час.
- **Послуги** — назва, опис, що входить, ціна («від»), тривалість, фото, показувати чи сховати, додати нову.
- **Фото** — головне фото і галерея «Наші роботи» (стискаються автоматично).
- **Контакти** — телефон, пошта, адреса, мапа, соцмережі.
- **Дні** — закрити день (зникає з вибору дат) або знову відкрити.

Правки власника зберігаються в базі й перекривають значення з `studio-config.js`. Кнопка «Скинути до значень із файлу» повертає початкові дані.

## Що змінюється лише у файлі `studio-config.js`

Назва, логотип, тексти Головної, графік роботи й кількість боксів, **питання й відповіді** (розділ «Питання»), часовий пояс. Назву й кольори в `manifest.webmanifest` теж правте вручну, якщо змінюєте назву студії.

> Відповіді в «Питаннях» — готові тексти, вони не підтягують ціни з кабінету. Якщо змінили ціни в кабінеті, за потреби оновіть і відповідь «Ціни» у `studio-config.js`.

## Відомі обмеження (чесно)

- **Спам-записи.** Клієнтам не потрібна реєстрація, тож зловмисник теоретично може забронювати час фейковими даними. Захист: мінімальний (прихована пастка для ботів і перевірка даних у базі). Власник бачить усі записи й може їх скасувати. Якщо така проблема з’явиться — додамо підтвердження по SMS або капчу.
- **Закриття дня** не скасовує вже існуючі записи на цей день — кабінет попереджає про них, зв’яжіться з клієнтами.
- **Сповіщень власнику немає** (SMS/Telegram/пошта): нові записи видно в кабінеті. Можна додати наступним кроком.
- **Оплати онлайн немає.**
- **Фото в демо-режимі** зберігаються в браузері й можуть вичерпати ліміт; у режимі Supabase ліміт — 5 МБ на фото.
- Офлайн-режим показує оболонку застосунку, але записатися без інтернету не можна.
- Після оновлення файлів на хостингу клієнти побачать нову версію з другого відкриття (кеш застосунку); щоб примусити — збільшіть `VERSION` у `sw.js`.

## Локальна перевірка

```
python3 -m http.server 8080      # у папці з файлами
```
Відкрийте `http://localhost:8080`. Службовий скрипт офлайн-режиму працює лише на `localhost` та `https`.
